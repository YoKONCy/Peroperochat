# 独立模式「轻透日常」UI 实装

## 范围

本轮把 `docs/design/standalone-prototype` 的房间、对话、衣柜与设置视觉接入正式应用，继续使用既有 Rust 对话、角色、日记、提醒和模型配置能力。未加载已放弃的自制动态立绘控制器或分层纹理缓存，也没有引入新的聊天工具。

远程客户端继续使用自己的主题、数据与连接逻辑；新样式限定在 `standalone-design` 容器。独立抽屉通过注入同步本地配色，远程抽屉优先使用远程主题。

## 两套角色显示

- 首页右上角的图片／模型按钮随时切换「静态立绘」和「Live2D」，菜单与设置的「显示与主题」也提供同一选项。
- 静态模式默认使用角色自己的素材；Pero 为原画 SVG，Nana 从 1.4.1 起使用独立的透明 PNG，替换旧默认 CG 卡片，自定义图片不覆盖。没有素材或图片失效时显示当前角色头像与显示设置入口，不借用其他角色的立绘。
- Live2D 使用原来的通用 Pio 接入和服装资源。角色状态、台词、环境信息与对话仍从 Rust 投影读取，两种显示共用同一角色身份，不创建第二份对话数据。
- 静态模式不加载 Pio。若之前已打开 Pio，则保留一个实例，但通过绘制循环的可见性入口停止续排动画帧；切回后恢复。页面隐藏、展开对话、软键盘展开或覆盖抽屉时也暂停绘制；衣柜保留可见预览。
- 模型异步初始化带版本号；切换显示或离开页面后，旧初始化结果不会重新启用模型。页面离开时移除事件与环境监听，隐藏模型并清空角色投影全局变量。

## 持久化与模式隔离

Rust `local::appearance` 提供 `local_appearance`、`local_save_appearance`，保存至独立数据库的 `ppc.ui.appearance`。通用 `save_config` 不写入该键。接口沿用独立模式令牌和数据库门禁；前端提交后再次核对令牌，模式切换会清空展示缓存。

| 字段 | 可用值 |
| --- | --- |
| `displayMode` | `illustration`、`live2d`，新配置默认静态立绘 |
| `palette` | `auto`、`sky`、`sakura`、`mint`、`violet` |
| `glass` | 60–94 的整数百分比 |
| `figureSize` | 44–64 的整数百分比，作用于静态立绘 |
| `motion` | 界面轻量过渡开关，优先遵循系统减少动态效果 |

保存成功后才更新显示，不乐观宣称已经持久化。保存期间禁用重复提交。偏好读取失败不阻断既有对话，显示设置提供重新读取和完整重存入口，允许显式修复损坏的显示配置。偏好随现有全量备份导出、恢复与重置。

## 角色素材

角色记录新增可选字段 `standing_image`、`room_background`、`illustration_layout`。旧角色由 Rust 补齐缺失默认值，显式空值保留；角色包的导入、复制、编辑与导出保留这些字段。原生投影返回 `presentation`，组件按投影绘制，不在页面里按角色名字选择图片。

- `illustration_layout` 为 `standing`（透明立绘）或 `card`（完整 CG 卡片）。
- 地址支持应用内素材、HTTP(S) 地址或 PNG／JPEG／WebP 的 Base64 图片；禁止任意本地文件路径和可执行协议。
- 编辑器允许选取不超过 5MB 的 PNG／JPEG／WebP，读取后作为角色记录保存；原生层再次验证类型、长度与排版枚举。换角色或退出编辑时取消未完成读取。
- 图片不包含用户脚本或样式执行能力。本轮未实现任意前端样式包安装器。

## 真实功能与视觉

聊天继续保留流式正文、思考、图片、停止、复制、重新生成、删除与历史定位；本轮统一头像、气泡、输入栏和面板轮廓。人物位置仍根据实际输入区和安全区定位，两种显示分别保持自身宽高比。

衣柜继续读取真实服装目录并由 Rust 保存选择。静态模式明确提示服装用于 Live2D，并提供切换入口；静态图不模拟换装成功。Live2D 资源加载失败保留重试和静态显示入口。

设置新增分组总览，连接、回复偏好、个人资料、角色、提醒、日记和数据管理仍使用现有接口。显示与主题同时可从房间抽屉访问。角色信息、名字与文案来自现有角色数据。

## 静态审阅与限制

本轮只进行了源码阅读、修改、调用关系与资源引用审阅。按照项目约定，未运行前后端测试、编译、构建、Tauri 或安卓打包，也未进行浏览器自动化验收。实际设备的布局、切换体验和 Pio 暂停恢复仍待用户启动后确认。
