# 单机纯聊天架构

本轮只收敛现有单机模式，保留前端样式，不加入工具调用、主子应用体系或远程托管协议。参考 infOS 的状态所有权和分层原则，在现有 Tauri/Rust 技术栈中实现精简的本地聊天运行时。

## 职责划分

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 页面 | `src/pages/` | 输入、展示、既有交互，不编译 Prompt 或写入消息事实 |
| 显示缓存 | `src/stores/agents.js`、`conversations.js` | 共享角色选择、按 Thread 隔离的可重建消息投影、流式预览 |
| 本地通信 | `src/services/` | 监听注册、请求身份匹配、取消和结构化错误 |
| 命令边界 | `src-tauri/src/local/mod.rs` | IPC 参数与本地资源装配 |
| 会话服务 | `local/conversation.rs` | 一轮请求的校验、上下文编译、模型调用、提交和终态 |
| 身份与配置 | `local/identity.rs` | 角色创建、导入冲突、复制、定义与台词的原子保存、模型配置和角色展示投影 |
| 设置提交 | `local/settings.rs` | API、模型参数和用户信息的校验与原子提交 |
| 群聊编排 | `local/group.rs` | 回复设置归一化、固定执行计划、整轮互斥与取消、共享一条用户输入 |
| 既有小游戏 | `local/blackjack.rs` | 发牌、牌局状态、算分、结算、自动点评和重复请求保护 |
| 环境信息 | `local/environment.rs` | 定位服务回退、天气解析、30 分钟缓存、后台刷新与一致提交 |
| 上下文编译 | `local/context.rs` | 只读消费人格、用户设定、相关记忆和已提交消息，按预算筛选历史 |
| 模型通信 | `local/provider.rs` | OpenAI 兼容接口、完整 SSE 事件缓存、超时、非流式响应和错误处理 |
| 持久存储 | `local/repository.rs` | Thread、消息、Pair、Revision、请求身份、软删除和迁移 |
| 旧元数据兼容 | `local/metadata.rs` | 严格解析 JSON，提交后更新已有角色状态、记忆等数据，不执行生成代码 |

SQLite 是单机业务事实的唯一权威。消息、记忆、角色状态和配置不再由页面双写到多个存储。

## 请求与生命周期

- 单聊使用每个角色自己的 `desktop:{agentId}` Thread；现有家庭群聊使用 `group:family` 的权威消息流，并在编译时按真实角色 ID 转换视角。
- 前端只提交当前输入或重新生成目标，不上传权威历史和完整 Prompt。
- 每次请求都有独立 `requestId`，流事件校验请求与 Thread；单聊同时校验角色，群聊用统一批次身份承接各成员的事件。
- 事件订阅注册成功后才发起 IPC。命令返回值负责成功或失败收尾，流不能因缺少结束事件无限等待。
- 单个 Thread 同时只能执行一轮；不同角色的 Thread 互相隔离。
- 点击首页原有输入按钮可在生成期间停止回复。取消会终止在飞网络请求；页面切换只停止该页面的观察，不取消后端执行。
- 重新生成保留原消息 ID 和时间戳；成功时保存旧修订并提交新正文，失败或取消时保留原回复。
- 中断和失败回复保留已收到的正文，但不作为成功的 assistant 消息进入下一轮上下文。进程重启时将遗留 pending 状态恢复为 interrupted。
- 群聊和小游戏复用同一会话服务。群聊由 Rust 一次执行完整计划，整轮持有 Thread 租约，页面离开不会终止后续成员回复。
- 小游戏仅提交开始、要牌或停牌操作；后端保管牌组和底牌，并校验牌局修订。结算后由同一后端命令自动生成点评；内部提醒是临时上下文，不混入用户消息记录。
- 角色编辑表单直接交给 Rust，后端派生闲置台词，并与角色定义在同一事务内提交；导入和复制的身份冲突处理也由后端负责。
- Live2D 仅消费后端角色投影和环境事件，不再从浏览器存储重新覆盖台词或配置；记忆标签筛选、模型偏好保存与天气缓存均由 Rust 负责。
- 前端保留表单草稿、角色选择、文件读取/下载、Markdown 渲染、动画、点击反馈和台词展示；这些界面行为不负责提交聊天事实或判定业务结果。

## 数据迁移与备份

- 原 `data/settings.json` 仅作为一次性迁移来源，原文件保留。后续配置保存在 SQLite `local_configs` 中。
- 原 `messages` 表和 `ppc.group.messages` 迁入 Thread 消息表，原记录不在启动时自动去重删除；迁移标记防止重复导入。
- 记忆新增稳定的 `source_message_id`。能唯一确认来源的旧记忆补全来源，无法确认的旧记录保留原字段。
- 备份版本升级为 `2.0`，包括 Thread、消息、修订、配置、记忆和现有提醒/话题；兼容显式导入原 `1.0` 备份。
- 导入先校验，再在同一 SQLite 事务中替换。任一步失败都会回滚，不能出现配置已覆盖而消息导入一半的情况。
- 重置覆盖所有角色的数据，并保留迁移标记，避免旧数据在下次启动时重新出现。
- 群聊执行计划与小游戏牌局属于本地运行状态，不进入可移植备份；导入/重置会一起清除，防止旧请求与恢复后的历史混用。
