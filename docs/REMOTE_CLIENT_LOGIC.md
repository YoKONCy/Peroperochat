## 2. 运行控制与切换

控制文件位于应用私有目录 `data/control/runtime.sqlite`。独立业务继续使用 `data/peropero.db` 与 `data/diary/`；远程使用 `data/remote/{profileId}/client.sqlite`。

控制投影包括：

```text
schemaVersion / revision / installationId / runtimeOwnerId
selectedTarget / activeTarget / activationEpoch
phase / switchId / lastError
```

目标格式为 `{ mode: 'standalone' }` 或 `{ mode: 'remote', profileId }`。活动令牌为 `{ installationId, target, epoch }`。

`mode_switch` 串行执行：先持久关闭运行门并递增代次，再通知前端、停止旧本地请求、断开远程观察连接、等待本地租约退出、进行受限取消清理、撤销系统登记，最后开放新目标。失败进入 `recovery_required`，活动目标为空；不会自动启用另一模式。

本地控制、JNI、桌面提醒通知及最终数据库提交使用相同控制 SQLite 的 `BEGIN IMMEDIATE` 短事务。控制事务先于业务数据库锁获取。网络与原生插件等待不持有控制事务；原生撤销有超时兜底，失败保持闭门。

启动先递增代次并关闭门，取得新的原生运行所有权。只有选中独立目标时，协调器才在闭门状态初始化独立角色及业务存储；远程启动不载入独立角色或执行独立业务迁移。系统撤销在主事件循环启动后执行，完成才开放选中目标；与用户切换共用切换锁。远程离线保留远程目标。另一应用进程接管后，旧进程即使读到新的稳定状态，也因所有权不符而失去业务与切换权限。

已被 infOS 接受的执行继续由服务端负责。本机切换不自动取消服务器任务；旧回调被拒绝不等于远程效果被回滚。

## 3. IPC 与前端服务

| 原生命令 | 调用方与含义 |
| --- | --- |
| `mode_snapshot`、`mode_switch` | `src/stores/mode.js`；读取运行权威、提交目标切换 |
| 现有独立命令 + 必填 `modeToken` | `src/services/localChat.js`；调用前后核对身份，原生存储边界再次检查 |
| `remote_profiles`、`remote_save_profile`、`remote_delete_profile` | `remoteConnections`；不返回凭据；当前选中配置不能删除 |
| `remote_query` | 受限的主体只读目录；可显式要求只读当前分区缓存 |
| `remote_action` | 受限写意图，每次携带稳定 `requestId` |
| `remote_chat` | 以持久客户端 UUID 提交服务端消息队列；Surface 从 Gateway 接收，执行与入队状态分别展示 |
| `remote_connect`、`remote_subscribe` | Gateway 身份握手与主体流订阅，原生负责重连 |
| `remote_surface_input` | 根据服务端请求确定角色，再获取输入席位并提交审批／回答 |
| `remote_pending_requests` | 查询当前分区尚待核对的写请求，不代表服务端任务状态 |
| `remote_upload`、`remote_resource` | 原生鉴权附件上传、头像／附件／带版本工作区资源读取 |

远程命令必须携带当前 `token`，响应与事件携带 `modeToken`。前端再次过滤，避免旧异步结果写入当前显示状态。运行控制的 `revision` 用于拒绝晚到的旧模式投影，不能与 Surface revision 或 Input Seat epoch 混用。

逻辑层调用示例（非自动运行脚本）：

```js
import { remoteConnections } from './services/remote'
import { switchMode } from './stores/mode'
import { readRemote, sendRemoteChat } from './stores/remote'

const profile = await remoteConnections.save({
  endpoint: 'https://用户指定的实例地址',
  token: '用户输入的凭据',
  allowInsecure: false,
})
await switchMode({ mode: 'remote', profileId: profile.id })
const threads = await readRemote({ kind: 'threads', agentId: 'pero', page: 1, pageSize: 20 })
// 使用服务端返回的真实会话 ID，不沿用独立模式的 desktop:pero。
await sendRemoteChat({ threadId: threads.items[0].id, agentId: 'pero', content: '你好' })
```

该示例解释 UI 如何调用服务层。根组件只在独立目标稳定时挂载独立页面，远程目标稳定时挂载独立的 `RemoteWorkspace`。2026-10-18 起独立房间菜单的远程入口暂时关闭；已有远程页的连接管理与返回独立模式能力保留。

## 4. 远程主体范围

当前只读目录包括：角色／状态／台词，分页会话与 Conversation Projection，会话工具，前台执行，审批和问题，分页后台任务／任务投影／行动清单，提醒，据点房间／成员／投影，分页事件记忆／来源，分页文档资料／详情，附件描述，工作区目录／版本化文件描述。

当前写目录包括：创建／改名／删除会话，聊天停止，交互与执行模式、会话工具配置，按修订编辑消息，撤回预览与明确撤回，后台任务派发与允许的控制动作，据点用户发言，以及统一 Surface 输入。普通消息仅按回滚规则撤回，不提供独立删除。保存并重新生成由原生层串接修订、回滚及入队，失败恢复按远程分区保存；工具执行始终留在 infOS。

订阅中的 `execution` 必须使用服务端真实 `executionId`，不能把后台 `taskId` 当作执行身份。当前提醒与部分待处理列表的服务端接口尚未提供统一分页，客户端以响应字节上限兜底，不声称能无限读取所有数据。

所有子应用、系统任意 HTTP 代理、桌面终端／浏览器控制、服务器配置后台、向量重建与全量数据库同步均未加入。

## 5. 隔离与恢复细节

- 连接配置不可原位改变地址或实例身份。新连接产生新 `profileId`，相同服务端或同名角色不自动合并分区；2026-10-20 起允许原连接重新授权，核对同一实例后更新独立凭据指针，活动连接同时撤销旧运行代次，详见第 10 节。
- 每次业务传输前重新核对保存的 `serverId`；认证失败、地址对应实例改变、协议不兼容时拒绝操作。
- 使用标准 TLS 验证，不跟随 HTTP 重定向。非回环明文 HTTP 必须显式允许；地址中不接受用户名、密码、查询参数与片段。
- 新远程凭据不进入 Vue Store、localStorage 或业务备份。旧 `remote_config` 只提取待确认地址，然后移除明文令牌；重新保存时需重新输入凭据。
- 当前凭据平台为 Windows 与 Android；其他平台返回不支持，不降级为明文。Android 云备份和换机规则排除控制库、远程缓存、远程加密凭据与提醒系统登记缓存。
- 投影缓存最多 64 个键、正文总计 32 MiB；单次 JSON／SSE／WS 消息限 8 MiB。请求墓碑独立保存，不因清理展示缓存而允许重复发送。
- 写请求先登记不含客户端请求 ID 的内容指纹与恢复上下文；相同身份不能换内容，相同内容存在未决记录时也拒绝用新身份重复发送。重启／切换后，旧运行代次遗留的 `sending` 转为 `unknown`；当前代次仍在发送的操作不会被核对接口提前终结。
- 原生错误增加可选 `outcome`，区分 `not_sent`、`rejected`、`failed` 和 `unknown`；只有明确连接失败或发送前错误才可判断未发送，HTTP 明确拒绝与服务端流错误分别记录。超时、异常响应、观察断开仍保留未知状态，绝不自动重放。
- 输入席位按交互请求真实角色获取。另一客户端抢先回答、席位失效或 Surface generation 改变时由服务端拒绝，手机刷新后再明确操作。
- Surface 合成保留节点、代次与序号；重复帧丢弃，缺帧标记需要刷新。可执行 `programmable-island` 与未知节点标记不支持，不在手机执行。
- 上传与单次资源读取限 8 MiB；大资源可按明确范围读取，工作区要求版本。媒体 Blob URL 在模式失效时释放，HTML／SVG 等主动内容不注入应用 DOM。

## 8. 静态审阅后的加固

- Surface 的 `surface.commit` 按 infOS 实际协议把预览身份替换为持久消息身份，保留最终描述自身的 revision／sequence；预览身份进入有界退役表，晚到的预览帧不会重新生成重复消息。失败的持久消息描述同样可以提交；会话与角色身份仍需一致。
- 冷启动先恢复当前分区的缓存与未决记录，再调用 `remote_connect` 登记原生恢复意图。角色可暂时为空，由原生读取本分区上次角色或向服务端发现；首次离线不会丢失恢复目标。前端初始化带代次隔离、重试去重及重试计时器，认证／实例身份／协议不兼容时停止自动重试。
- Gateway 将期望订阅与已确认订阅分开保存；订阅失败撤销连接，监督循环重建并补齐。只有完成订阅恢复才发布在线事件，断线事件携带 sessionId，前端拒绝旧连接晚到的断线事件。恢复订阅仅刷新读模型，不重新发送写操作。
- 缓存查询在发起时取得持久化读票据，只有该键最新票据能写缓存。写请求登记及回执提交都会在事务内失效投影与票据；旧查询也不能回填前端。网络不可用时允许读取明确标识为过期的缓存，认证或实例身份变化不触发此兜底。
- 请求库兼容迁移新增上下文及运行所有者字段，记录聊天／操作／交互／上传元数据、已经观察到的 executionId／messageId 和有界结果回执。未决记录最多 100 条、上下文合计 8 MiB；已终结操作只保留最近 64 条详细记录，身份和指纹墓碑不因清理而失效。旧版本缺少上下文的记录无法补造，继续保留待核对状态。
- `remote_pending_requests` 接入启动、在线恢复及写请求结束后的前端恢复；`remote_reconcile_request` 只在已经观察到持久 messageId、服务端权威投影确认相同会话／角色／消息时终结未知聊天，默认只查询最近 60 条，找不到不代表未执行。自动核对与显式核对的状态更新使用事务条件检查。
- `remote_review_request` 与前端 `reviewRemoteRequest` 供后续 UI 接入显式核对，需要请求指纹与非空核对说明；只记录用户已核对，不伪造服务端执行结果，不重发原请求。其他无法证明结果的操作保留 `unknown`，完整服务端幂等与接受状态查询合同仍待双方继续实现。
- 前端展示缓存与持久化未决列表分离；明确拒绝／未发送错误不会被当成未决请求占满 30 个活跃展示名额。核对记录读取错误通过 `pendingError` 单独暴露，不覆盖原写请求的真实返回结果。
- 同步修复本地 infOS 源码中的 Gateway 服务端鉴权：构造时注入 `INFOS_API_TOKEN`，升级请求验证 Bearer 或浏览器查询凭据，hello 复用已经验证的传输身份；未握手连接不能通过 abort／push 等分支绕过鉴权。增加握手期限和消息大小上限。此修复须在对应 infOS 服务端同步部署后生效。

本次仅做源码修改、调用链静态复查和 Git 差异检查，未运行任何测试、构建或服务；UI／UX 未改动。

- **会话**：默认恢复本连接的上次会话，首次连接进入角色／会话选择。接入新建、改名、删除、流式回复、停止、附件上传、受控附件预览、历史分页和行动清单。会话失效时清理上次选择并返回列表，草稿仍保存在原会话作用域。
- **角色展示**：迎接区约占可用高度 22%，历史阅读、输入、导航与详情使用紧凑头像。展开偏好按远程角色分别保存；服务端没有模型契约时使用服务端头像，可明确选择本机内置 Pio 展示素材，素材与独立模式的业务、台词及角色设置隔离。iframe 只加载本机渲染引擎和固定素材路径；收起、离开页面及应用隐藏时移除渲染上下文。
- **任务**：分页查看角色任务、任务 Surface、执行进展、结果和关联会话，按实际状态显示允许的暂停／继续／重试／取消操作。取消需明确确认。
- **通知**：汇集审批、求助问题、待核对请求和最近 256 条持久通知缓存。通知明确标为已读后发送对应版本的服务端回执；审批及问题跳转对应会话或任务，使用实际 Surface 身份与原生输入席位提交，预览中的交互等待权威投影同步后才能操作。此页不代表已支持关闭应用后的推送，通知完整分页及业务对象跳转仍待完善。
- **资料**：分页检索角色事件记忆、来源对话、文档与片段摘要，以及当前会话的文件目录、带版本的文件读取。文档详情目前遵循现有元数据／摘要接口，全文展开与资料编辑仍需后续接口接入。

新增 `remote_ui_read`／`remote_ui_write`，仅接受 Home、Session、Character 三类有限作用域，存储在 `data/remote/{profileId}/client.sqlite`。草稿、附件草稿引用、阅读锚点／偏移／分页游标，以及展示偏好均不写入 localStorage 或独立数据库。值由 Rust 校验，记录总数上限 256、正文总计 8 MiB，单份草稿上限 128 KiB；支持明确重置某条会话的本机记录。

草稿保存编辑身份和发送请求身份。仅当原生请求库已有 `completed` 持久回执时，读写该草稿才会清理原发送内容；后续新编辑解除旧发送关联。读取会等待之前排队的保存，原生写入同样核对完成回执，避免延迟保存复活已发送草稿。应用关闭、切换会话或结果未知不会被当成已成功发送，未知操作仍通过原生核对接口处理。

远程历史视图最多保留 4 页，按锚点恢复用户阅读位置，正在阅读时不自动滚动到底部；迎接区动画结束后再次对齐位置，快速切换会话不会沿用旧历史加载状态。最终投影读取失败时暂时保留流中已收到的持久消息，由成功刷新的服务端投影接替。头像请求复用并限制并发，缓存按模式失效释放；附件和文件使用鉴权原生读取与受控 Blob，HTML／SVG 内容以纯文本读取，远程 Markdown 不自动加载外部图片、脚本或可执行岛。外部链接经显式点击交给系统浏览器。

## 10. 新版 infOS 手机 Web 接入适配（2026-10-20）

本节记录源码适配，参考本地 infOS `4fa14246` 加当时未提交的客户端接入实现，尚不能作为已发布、跨版本稳定协议声明。远程入口继续显示「暂未开放」；未改动 infOS 源码，也未运行任何检查程序、测试、构建或服务，仅人工审阅源码与 Git 差异。

- `remote_save_profile` 新增运行令牌与有限认证方式：`pair` 使用一次性配对码，`login` 使用管理凭据兑换设备会话，`bearer` 为显式兼容模式。表单默认配对，不自动降级或重放配对请求。设备名、有效期与设备身份用于连接展示；失败信息不回显凭据。配对响应丢失时提示核对设备并重新生成代码，不自动再次兑换。
- Rust 从 `Set-Cookie` 提取 `infos_device`，核对 `/api/client-access/status` 与稳定实例身份。设备令牌只进入原生系统保护存储，后续原生 HTTP／SSE／WS 使用同一设备令牌的 Bearer 鉴权。Cookie 不交给 WebView，前端只接收设备元数据。未勾选「保持登录 30 天」时，授权绑定本次原生进程所有者，重启后拒绝复用并清理本机密钥；服务端自身的短会话期限仍为最多一天。普通设备无管理权限返回 `REMOTE_FORBIDDEN`，401 才使当前连接进入重新授权状态。
- 连接分区身份与凭据存储键分离，旧连接缺少新字段时仍使用原安全存储键。重新授权只能保持相同地址和 `serverId`，新密钥先单独落盘，再原子替换配置指针。更新活动连接时关闭运行门、递增代次、停止旧观察连接后重新激活，原分区的草稿、阅读位置与请求墓碑保留；失败保持闭门或保留原配置。旧密钥在成功后清理。重新授权不会自动撤销服务端的旧设备记录，可通过 infOS 设备管理单独撤销。
- `remote_session_status` 检查设备授权；`remote_logout_device` 明确注销当前设备会话，不删除远程业务与本机阅读记录。凭据过期、服务端撤销、HTTP 401 或带授权失效原因的 WS 关闭会停止自动重连，保留远程目标；不会启用独立模式。返回前台重新核对授权并重建 WS，随后刷新读模型，不重新发送聊天、审批或任务操作。
- WS 升级通过 Bearer 鉴权，`hello` 不再重复发送凭据，以兼容设备令牌与管理凭据分离的新版服务端。Gateway RPC 错误只映射有限错误码，握手 Session、角色、窗口及席位代次仍核对。输入提交在 Rust 串行化；获取席位失败可重连一次，业务提交仅在服务端明确返回席位缺失／过期／身份不匹配且尚无副作用时恢复一次，网络超时与其他失败不自动重放。
- Gateway 按流记录本次运行的 sequence，重订阅传回真实游标并消费补发事件，按事件身份去重；事件缺口、保留窗口过期或服务端序号回退触发权威快照刷新。游标不跨模式或连接复用，进程重启从零恢复，结合快照和服务端持久未读通知补送，不把进程内序号当作永久业务位置。
- 持久通知保存在当前连接 `client.sqlite` 的独立表中，保留最近 256 条，正文展示限 4096 字符；截取展示正文不会改变服务端原记录。服务端未读状态仍是权威，超出本机缓存窗口的通知不会被自动确认。`remote_notifications` 可离线读取；`remote_ack_notification` 只允许确认本机收到的同一通知版本，经明确「标为已读」动作发送回执，成功后清理本机匹配版本。回执超时保留记录，不自动重发；重复明确确认由服务端通知 ID／revision 幂等处理。
